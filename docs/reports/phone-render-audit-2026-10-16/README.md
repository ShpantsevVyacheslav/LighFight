## Confirmed pipeline and costs

- Prototype.cs:44–62 creates one fight camera, one directional light, FittedFilmicCamera and ambient light. BeginFight():67 restores both actors+arena, disables selection-display camera and releases selection RT. FightSelection.cs:54,60–82: roster disables player and fight camera, releases preview HDR/MSAA target; preview uses one actor camera into scaled target plus cullingMask=0 display-clear camera. No production manual Camera.Render call is on this path. Thus do not assume two fight renders from the old dense benchmark; count onPreCull in actual player.
- FittedFilmicCamera.cs:10–15 forces HDR and performs a fullscreen ACES-fit Graphics.Blit every enabled camera render. Linear, original PBR and tonemap are accepted visual behavior; removing them is a visual change. Actual fight HDR intermediate format/MSAA resolve/store cost is driver-dependent and must be captured, not inferred from preview RenderTexture fields.
- FightOptions.cs:11–13 defaults Max/60/shadows ON; sets mip limit0, Unlimited skin weights, Max AA4/High-shadow-resolution/lod4; High and Battery both AA2/Medium-shadow-resolution/lod2. All three retain original maps and full battle display resolution. Battery vs High differs only preview resolution via FightSelection.cs:45–51 (.65 vs .85, Max1). Selecting Battery therefore is not a distinct lower-work fight renderer. No runtime SetQualityLevel or fight Screen.SetResolution appears on inspected shipping path.
- QualitySettings.asset iPhone platform default index2 (Medium): pixelLightCount1, one cascade, vSync1. ApplyOptions overrides AA/shadows/resolution/distance/lod but not the index/cascade count/pixel lights. Calling app Max does not select Unity Ultra. Runtime inventory still needed because host/imported PlayerSettings can differ.
- Native artist `native-pbr.mat` references built-in Standard shader (fileID46), including current scalar variants. Do not benchmark CharacterSkin shader as the native roster workload. Soft directional shadow maps and Standard shadow/lighting passes add work beyond camera-visible color pixels. Prototype.cs:99–101/FightOptions.cs:12 force arena renderers to cast and receive shadows; eligibility pruning needs full visible-shadow bounds evidence, not merely camera-frustum visibility.
- Catalog prefab direct serialized inventory is `catalog-serialized-inventory.json`: actors use Animator culling0/AlwaysAnimate and SkinnedMesh updateWhenOffscreen1. Direct counts omit nested imported dependencies. These settings preserve contacts/native clips/shadows. Globally changing animator culling or offscreen updates risks geometry/contact divergence; no blanket flip proposed.
- ProjectSettings meshDeformation0 is CPU skinning. GPU mode may preserve quality but existing Mac dense evidence had timing tails/missing valid GPU timings, so not an accepted default or a phone gain. Current ~100k actors need independent device-quality and tail proof before any change.

## Concrete avoidable work / lifecycle risk

- Prototype.cs:151–161 `optionsOpen` and paused/backgrounded/timeScale gates return only from Prototype.Update. Cameras and actor components remain enabled. FighterView.LateUpdate (63), NativeFingerPoseDriver.LateUpdate (22), NativeSupportOverlay.LateUpdate (49), CandidateFootGrounding.Update/LateUpdate (10) still execute while hierarchy active. A stopped simulation is not a stopped renderer; even dt0 can run transforms, state lookup, grounding and raster/HDR/blit. This is source-confirmed eligibility to work, not a measured phone contribution.
- Prototype checks backgrounded/timeScale only AFTER selecting branch. HostBridge.Pause sets timeScale0 only (33); Exit also timeScale0 (34). Selection can keep its update/renderer path eligible under host pause, unless native host pauses Unity itself. OnApplicationPause clears input/core accumulator but does not explicitly suspend camera/actors. Native iOS/Unity may stop its loop on OS background; do not claim background GPU runs from C# alone. Explicit host pause while Unity remains foreground is the repro target.
- OpenOptions (FightOptions.cs:14) opens .8-alpha modal over fight; scene stays visible. Disabling the camera alone would erase/change the backdrop. A correct optimization needs a frozen rendered backdrop, not a black screen, missing UI or repeated HDR tonemapping.

## Minimal suspension proposal and regressions (not applied)

Use one typed suspension owner rather than independent camera/actor toggles. Enter after actual EOF: record which objects/components were active/enabled, capture FINAL display-color backdrop outside measured windows (not source HDR, no double tonemap), then stop 3D camera/actor hierarchy. Keep clear/display UI rendering and host bridge active. Modal UI remains composited over identical backdrop. Preserve resident warmup leases; suspension is not content unload. Resume restores exact recorded flags, discards backdrop and zeros simulation accumulator; does not reset Fighter/session/native curves, replay stale contact cache or advance elapsed simulation by paused walltime. Integrate roster/ActorsLoading ownership so closing options cannot reactivate hidden roster actors, and BeginFight cannot destroy a target still referenced by UI. Background host behavior requires native lifecycle evidence before changing it.

Regression gates: (1) frozen final backdrop pixel-identical with overlay alpha/UI excluded; (2) after warm suspension zero scene onPreCull/actor pose/finger/overlay/grounding ticks, UI and touch still responsive; (3) 60s hold then resume exact core state, no catch-up burst or input attack; (4) current native/full-source EOF/contact/floor parity and same next-frame animation phase; (5) repeated options/roster/preview/fight/hostPause/Exit/Launch transitions no orphan RT/actor activation, all leases released on true unload; (6) preserve exact source material/dependency SHA and all max settings. This is a reviewable implementation contract, not a claim that cached fight rendering is already implemented.
