# Arena generation: official capability check

Reviewed2026-10-15; no credit spend or new generation from this check.

Meshy officially lists a Scene workspace. The overview does not establish that this exports a photo-reconstructed playable Unity level. Its separate 3D-to-Image description uses arranged models to generate images; that image workflow alone is insufficient evidence of an arena mesh/collision/export. Actual Scene UI/export must be inspected before attributing either capability or limitation to the whole module. [Meshy overview](https://docs.meshy.ai/en), [Meshy feature reference](https://help.meshy.ai/en/articles/9991738-what-features-does-meshy-have).

Tripo's official scene workflow distinguishes editable meshes/layout from a rendered view and recommends reviewing individual assets, consistent scale/materials and target-engine checks. It explicitly warns that a generated village model is not automatically an assembled editable environment. This supports the current component approach; it does not certify our current courtyard draft. [Tripo scene workflow](https://www.tripo3d.ai/blog/3d-scene-generation).

Current local verdict: source-photo component courtyard has improved gravel and working shadows, but sparse repeated trees, bare walls and blue void failed visual resemblance. Do not promote as the finished courtyard. Next concrete arena gate: inspect Meshy Scene actual export without credit spend; separately improve photo-specific wall/door/car/tree composition, then validate attack camera range, playable clearance, collisions and mobile render budget. Whole-scene Tripo diorama and Meshy character-like yard results remain rejected. Existing arena5 in the embedded proof is the current catalog prefab, not acceptance of the new courtyard draft.
