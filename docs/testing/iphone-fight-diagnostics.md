# Диагностика LighFight на iPhone

Сборка107 содержит source e31c6fa и Release IL2CPP / Development=false. Наличие этого manifest не доказывает, что именно эта версия установлена на устройстве. Новая диагностическая версия должна показывать фактическую embedded content version в журнале.

## На экране и в журнале

В новой сборке: **настройки боя → Диагностика: ON → Закрыть**. По умолчанию OFF, выбор сохраняется. В бою появится панель без кнопок, не захватывающая свайпы:

- FPS и p95 времени кадра за последнее окно около1секунды;
- GPU-время, только если FrameTimingStats уже включён и получен достоверный новый отсчёт; иначе unavailable;
- CPU процесса в эквивалентах ядер (1,0 = одно ядро полностью занято), память всего процесса-хоста;
- тепловое состояние iOS nominal / fair / serious / critical и режим энергосбережения. Это не температура в°C, а serious само по себе не доказывает величину троттлинга.

Счётчики не меняют качество, FPS, тени, режим скиннинга или глобальное профилирование. Сетевого пинга в текущем локальном бою против бота нет. CPU/память процесса включают и LighChat, и Unity; разделить их работу позволяет трасса.

Один отсчёт в секунду пишется в Console с префиксом `LF_DIAG` и CSV в `Application.persistentDataPath/Diagnostics`. Один файл ограничен20минутами/1200строками; выключение диагностики закрывает файл, повторное включение начинает новый. При фоне окно сбрасывается, чтобы время вне игры не считалось зависанием. Недоступные показатели не заменяются нулями. Диагностика имеет небольшую собственную нагрузку, поэтому сравнивать нужно одинаково инструментированные прогоны.

## Онлайн на Mac

1. Подключить разблокированный iPhone к Mac, подтвердить доверие; при необходимости включить Developer Mode. Открыть LighChat и бой.
2. В Instruments выбрать iPhone и процесс LighChat (`Runner` — имя проверяется в списке процессов). Начать с **Game Performance**: CPU/Metal, время кадров, тепловое состояние. Для энергии отдельным сопоставимым прогоном — **Power Profiler**. Оба шаблона найдены в установленном Xcode.
3. В Console.app выбрать подключённый iPhone и фильтр `LF_DIAG`, либо смотреть вывод процесса через Xcode. Наличие такого вывода на этом телефоне ещё требует подключения; сейчас в проверке устройство Offline.
4. Для детального Unity Profiler нужен отдельный Development-плеер, подключаемый к Editor. Его накладные расходы меняют измеряемую нагрузку; не заменять им обычную Release-версию при итоговой проверке нагрева. Deep Profiling по умолчанию не включать.

Read-only CLI для10минутной трассы (создаёт новый файл, существующий не перезаписывает):

```sh
./scripts/record-iphone-fight.sh DEVICE_UDID Runner /absolute/new-run.trace game
```

Второй отдельный прогон с `power` вместо `game` выбирает Power Profiler. Команда ещё не исполнялась на iPhone: нужен доступный разблокированный аппарат. Она не устанавливает приложения, не меняет настройки и не собирает данные остальных процессов через all-processes.

Журнал можно получить из контейнера приложения через Xcode Devices → Download Container. Для установленного bundle ID и обычного iOS Documents-пути также доступна read-only команда `xcrun devicectl device copy from --device DEVICE_UDID --domain-type appDataContainer --domain-identifier BUNDLE_ID --source Documents/Diagnostics --destination /absolute/new-directory`. Реальный путь проверяется по `LogPath`; доступ к контейнеру зависит от подписи/Developer Mode. На устройстве эта выгрузка пока не проверена.

## Сопоставимый тест нагрева

Одинаковые бойцы/арена/графика/FPS/яркость, прохладное исходное состояние; записать, подключена ли зарядка. USB-подключение само меняет условия питания, поэтому сравнения проводить в одинаковых условиях. В течение10–15минут повторять обычные удары, удары ногами/в прыжке, падения и подъёмы. Отмечать момент появления нагрева и снижения плавности; сопоставлять его с p95, CPU/GPU и тепловыми переходами. Частые кадры с60FPS не доказывают низкий расход энергии. Отдельно отличать секундные пики, устойчивую загрузку и память.

Источники: [Apple: Game Performance / Metal](https://developer.apple.com/documentation/xcode/analyzing-the-performance-of-your-metal-app/), [Apple: Power Profiler](https://developer.apple.com/documentation/Xcode/measuring-your-app-s-power-use-with-power-profiler), [Unity: профилирование iOS](https://docs.unity.com/en-us/engine/6000.0/manual/platform-specific/iphone/ios-developing/ios-testing-and-debugging/ios-profile-device).
